## #2 已購書不再誤跳「授權已失效」 🔍

| 步驟 | 預期 |
|---|---|
| 用**已購 20 本以上**的帳號，從「繼續觀看」點最早購買的那幾本 | 直接回到存檔進度，不跳「此故事尚未解鎖或授權已失效」 |
| 看 log `[bookAccessService] 權威持有清單 →` | `count` 等於實際已購數、`total` 與後端一致；`pages` > 1 代表後端確實有壓每頁上限 |
| 金幣紀錄頁 | 較早的解鎖紀錄也顯示書名（不是訂單編號） |
| 斷網後從繼續觀看點已購書 | 不跳授權失效（狀態未知時放行），回到存檔位置 |

## #3 #5 授權失效按確認後回主頁 🛠

前置：後台把測試帳號某本**付費書**移出書單（撤銷 entitlement），且該帳號有這本書的閱讀存檔。

| 步驟 | 預期 |
|---|---|
| 不分章節書：繼續觀看 → 點該書 | 跳「無法繼續閱讀／此故事尚未解鎖或授權已失效」 |
| 按確認 | 回到**主頁**，不進故事頁、不會停在試閱場 |
| 分章節書（存檔位置在付費章節）：同上 | 按確認後同樣回**主頁**，不進章節列表 |
| 分章節書（存檔位置仍在試閱範圍）：同上 | 不跳提示，照常回到試閱進度（試閱讀者本來就讀得到） |
| 首頁點該書 → 簡介彈窗右鍵（繼續閱讀） | 同上述行為 |
| 後台把書加回書單 → 再從繼續觀看點 | 回到**原本的存檔進度**（存檔沒有被清掉） |
| 回歸：role ≥ 5（小編）帳號 | 不受影響，直接可讀 |

## #4 已下架的書不出現在書櫃 🛠

| 步驟 | 預期 |
|---|---|
| 後台下架一本測試帳號已購的書 → 一般帳號打開「我的書籍」 | 該書消失 |
| 小編帳號（role ≥ 5）打開「我的書籍」 | 該書仍在（預覽者可見） |
| 斷網後打開「我的書籍」 | 不會因為書店清單取不到就清空書櫃 |
| 後台重新上架 | 書回到書櫃 |

## #6 內購失敗提示 🔍

| 步驟 | 預期 |
|---|---|
| 商城購買時在付款畫面按取消 | 不跳任何錯誤彈窗 |
| 付款成功、後端驗證失敗（例如 iOS 模擬器用本機 StoreKit 設定檔購買，後端無法驗證本機收據；或請後端暫時讓 `api/iap/verify` 回失敗） | **只跳一個**彈窗：「金幣尚未確認入帳／付款可能已完成…請勿重複購買…」並附**交易編號**；**不再**跳「載入商品失敗」 |
| 上一步後查看金幣餘額 | 已自動刷新一次；若後端其實已入帳會顯示新餘額 |
| 進商城時後端金幣包或商店連不上 | 照常跳「載入商品失敗」（此行為不變） |
| 正常購買成功 | 跳「購買成功」，金幣增加（行為不變） |

### 書籍已退款標註 🛠

前置：CMS 會員書單對某本**用金幣買的書**按「移除」（寫入 0 金幣的「[已退款] 書名 ORDER:n」流水，書籍保留、金幣不退）。

| 步驟 | 預期 |
|---|---|
| 開「金幣紀錄」看最新那筆 | 標題「書名 - 已退款」，金額顯示 `0`（不是 `+0`），不顯示 ORDER 編號，**不再**出現「管理員授權」 |
| 同一本書原本的解鎖紀錄 | 維持「書名 - 解鎖」與原扣款金額，不加註已退款（金幣並未退回） |
| 兩列書名 | 相同（以 App 顯示的書名為準） |
| 本機配不到書名的舊解鎖紀錄被標註退款 | 解鎖列改顯示 CMS 寫入的書名，不再只顯示「故事解鎖」 |
| 後台另以「添加獎勵」手動補金幣 | 仍顯示「管理員授權」與實際金額（行為不變） |
| 切英文語系 | 「書名 - Refunded」；查無書名時為「Story Refunded」 |

### 書櫃隱藏已退款書籍 🛠

前置同上。判定與 CMS 書單頁相同：CMS 該列顯示「已退款」的書，App「我的收藏」就不顯示。

| 步驟 | 預期 |
|---|---|
| CMS 按「移除」後，App 切到別頁再回「我的收藏」 | 該書不見；CMS 書單頁該列為「已退款」 |
| 停在「我的收藏」，App 切背景 → CMS 移除 → 回前景 | 該書消失 |
| 同帳號其他未退款的書 | 照常顯示 |
| CMS 移除後無法標註的書（後台贈書，CMS 會報「找不到金幣購買紀錄」） | 照常顯示 |
| 讓帳本 API 失敗（`api/me/coins/ledger`）後開「我的收藏」 | 已退款的書暫時又出現（無法判定時不隱藏）；恢復後再進一次即消失 |
| 首頁／繼續觀看點已退款的書 | 見下方「已退款書籍不可再讀付費內容」 |

### 已退款書籍不可再讀付費內容 🛠

前置同上（CMS 按「移除」，擁有權**不**收回，只有已退款標註）。準備一本分章節、一本不分章節的付費書，各有「未開放試閱」內容，先在測試機上購買並讀到付費範圍、留下繼續觀看存檔。

| 步驟 | 預期 |
|---|---|
| 從「繼續觀看」點存檔落點在付費範圍的書 | 跳「需重新解鎖」後回主頁；存檔保留；log 有「此書已被標註為已退款，視為未持有」 |
| 存檔落點仍在試閱範圍內的書 | 照常還原，讀到試閱結束才跳解鎖 |
| 「再次回味」點已退款的書 | 跳「需重新解鎖」後回主頁 |
| 首頁點已退款的書 →「從頭開始」 | 讀到試閱範圍尾即上鎖並跳解鎖列；分章節書的章節列表未開放章節上鎖 |
| 閱讀中於 CMS 移除，App 切背景再回前景 | 鎖住推進並跳購買提示 |
| 讓帳本 API 失敗（`api/me/coins/ledger`）後點已退款的書 | 無法判定退款 → 照常可讀；log 有「帳本取不到，無法判定是否已退款」 |
| 回歸：未退款的已購書 | 照常可讀 |
| 已退款後在 App 內重新購買同一本書 | ⚠️ 待確認後端行為（是否允許重買、entitlements 建立時間是否更新）；若重買後仍被鎖，需後端配合 |

## 書櫃：後台收回擁有權後不可再讀 🛠🔍

前置：CMS 書單「移除」**不會**收回擁有權（只寫已退款標註）。真正收回需以 role>=9 帳號呼叫 `DELETE /api/admin/users/{userId}/entitlements/{bookId}`（Swagger）。準備一本**分章節**、一本**不分章節**的付費書，兩者都要有「未開放試閱」的內容，並先在測試機上購買。

| 步驟 | 預期 |
|---|---|
| 收回後，切到別頁再回「我的收藏」 | 書不見 |
| 停在「我的收藏」，App 切背景 → 收回 → 回前景 | 書消失（不必切換畫面） |
| 收回後先線上進一次「我的收藏」再切走、再進一次；接著讓擁有權 API 失敗（封鎖 `20.198.216.126:3001`，`xstoryline.com` 正常） | 書不會再出現；log 有「連續兩次不在權威清單內，自本機快取移除」 |
| 分章節書閱讀中收回，App 一直在前景，讀到章末自動接下一章（未開放試閱） | 新章一進來就上鎖並跳解鎖列，不能再往下讀 |
| 「我的收藏」開著時收回不分章節書，立刻點它 →「重新閱讀」 | 一進來就上鎖並跳解鎖列（舊版整本可讀） |
| 登出再登入，**不進首頁**，直接從「我的收藏」點已收回的書 →「繼續閱讀」 | 跳「需重新解鎖」後回主頁 |
| 回歸：未收回的已購書，讓擁有權 API 失敗後從「繼續觀看」進未開放章節 | 照常可讀，不跳解鎖列 |
| 回歸：在**別台裝置**購買的書，本機線上開過一次「我的收藏」後再讓擁有權 API 失敗 | 書仍在書櫃且可讀 |
| 回歸：剛購買立即「開始閱讀」 | 完整內容，不被鎖 |

## P1 #10 已領過獎勵不再誤報

| 步驟 | 預期 |
|---|---|
| 已領過「完成個人資料」獎勵、但生日或性別被清空的帳號，進個人資料頁 | 底部是一般「更新」按鈕，不再出現「完成並領取 50 金幣」 |
| 修改資料後按更新 | 「個人資料已更新」成功提示，不出現「領取獎勵失敗」 |
| 若帳本暫時取不到、仍出現領取按鈕，按下後後端回絕 | 顯示「個人資料已更新／您已領取過此活動獎勵，不會重複發放」，不是錯誤 |
| 從未領過的新帳號完成資料 | 照常領取 50 金幣（行為不變） |

## 已知未修（待後端確認後處理）

- 後端驗證失敗時，App 仍會 `finishTransaction` 把交易結束掉，商店不會重送、金幣不會自動補發。要改成「驗證成功才結束、失敗保留並自動重驗」，**前提是 `api/iap/verify` 對同一筆 transactionId / purchaseToken 冪等**（重送不重複加幣）。
- #2：2026-10-13 以測試帳號實測，`GET api/me/entitlements` 有回傳 `total`、`limit`，且照請求的 limit 回傳（limit=100 回 100）。**目前後端不會觸發舊的分頁錯誤**，分頁修正屬防禦性質；QA 回報的誤判真正原因仍待重現（請提供觸發的帳號、書名、當下語系，並擷取 `[bookAccessService] 權威持有清單 →` 與 `[Book] 付費書未持有` 的 log）。
